## 为什么把 HAL 抽出来

`machine.c` 不认识任何寄存器，只认 `hal.h` 里那张函数表。
好处很直接：状态机——**也就是最容易被写错的"什么时候回 OK、什么时候回 DONE、
什么时候该停机"**——能在 PC 上用假 HAL 全部测完。

真机上唯一要换的就是 `main_stm32.c` 里那张表的实现。改了 PLC 接线、换了驱动器，
状态机一行不用动。

## 和上位机怎么对齐

协议细节见 `sorting/core/protocol.py`，两边必须逐字一致：

```
收到指令         → 立刻回 OK
运动走完         → 回 DONE
夹爪走完         → 先 DONE，再 GRIPD <实际停止位置>
超程 / 找不到限位 → ERR E01 / E02  且进 FAULT（位置已不可信）
未知指令 / 参数错 → ERR E03        **不进 FAULT**（拼错一行不该停机）
夹爪超时         → ERR E04        **不进 FAULT**（卡住一件不该停整台）
```

两道独立的超时闸：上位机那 15 s 是防 MCU 死掉，固件这边几百 ms ~ 几秒
是防某一根轴被卡住。两边都保留，不要删掉其中一边。

## 上板还要补的（按顺序）

1. **`axis_step_isr` 的加速段**——现在是等速 + 计步，加速曲线要按已经走过的
   步数反算周期。不补的话高速会丢步，位置就永久错了。
2. **`g_pos_steps` 累加**——现在 `hal_position_mm` 还返回 0。这个必须在发脉冲
   的地方累加，**不能用目标位置代替**：丢步时目标位置照样是对的。
3. **`tmc_write` 的 CRC8**——TMC2209 单线 UART 每帧最后一位是 CRC8-ATM。
   补错了寄存器根本写不进去，而且不会报错，只会表现为"StallGuard 没反应"。
4. **`hal_home` 的真实流程**——四个轴依次回零，低速前进 → 撞限位 → 后退 2mm
   → 再慢速逼近 → 清零。超时置 `g_home_failed`。
5. **限位 EXTI**——上升沿触发，置标志位给状态机看。
6. **看门狗**——`HAL_IWDG_Refresh` 现在无条件喂，真机上应该只在主循环正常
   跑完一圈时喂。
7. **`txbuf` 双缓冲互斥**——DMA 还在发的时候不能覆盖。现在只留了注释。

## 明确没做的

- 多轴联动插补（现在 XY 是各自独立走梯形，不保证同时到达；对 200mm 的行程
  误差在几十毫秒级，先接受）
- 丢步检测（需要编码器或和限位对账，硬件还没有）
- 掉电位置保持
- 电流闭环
