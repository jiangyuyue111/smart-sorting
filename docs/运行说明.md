# 怎么运行 / 怎么演示

> 面向"打开就能跑"，不需要懂代码。所有命令都在 **PowerShell** 里执行。
> 目前没有硬件，所以全部用模拟 MCU + 合成托盘图，跑出来的图和数字都是真的，
> 只是不经过真机。
>
> **要拿去讲给评委听，看 [`答辩口径.md`](答辩口径.md)** —— 那里是逐句话术，
> 包括"硬件还没到怎么说""50.8 秒怎么解释""被追问时怎么答"。

## 1. 演示：打开工作台（推荐，一个网页看完）

```powershell
python -m sorting.app.studio
```

浏览器会自己打开 **http://127.0.0.1:8765**。这就是全部操作。

工作台里能同时看到四样东西：

| 位置 | 看什么 |
|---|---|
| 左边大画面 | 机器在托盘上方一件一件动，X/Y/Z 和夹爪都是实时位置 |
| 左下"原理 · 内部实况" | **同一时刻**串口上真正发出去的指令、像素怎么变成毫米、这一步为什么这样走 |
| 右边屏幕 | 480×320 那块屏现在的画面（和真机同一份渲染代码） |
| 右边参数 | 改速度、改高度，点一下立刻重算整轮，节拍跟着变 |

底下有一条**时间轴**，可以拖着回放已经跑完的 50 秒，看任意时刻机器在哪、
屏上显示什么。点 **▶播放** 就是从头放一遍。

右上角两个按钮：

- **实跑一轮** —— 真的从头执行一遍，屏幕和进度条跟着走（现在走模拟 MCU）
- **▶播放** —— 只回放已经算好的结果，快进倍速可调

> 等硬件到了，同一条命令加 `--serial COM3` 就变成接真机：
> `python -m sorting.app.studio --serial COM3`。
> **页面不用改，代码也不用改**——预演和实机走的是同一份数据结构和同一份渲染代码。

`原理` 那一块是专门为了不搞黑箱留的：评委问"你怎么知道它算得对"，
可以直接指着那一栏说"这一行就是当前发出去的指令"。

不想开浏览器、只想确认动画没算错：

```powershell
python -m sorting.app.studio --selftest
# → ✓ 自检通过（136 段运动 / 12 件）
```

它会断言：录下来的时间轴末尾 == 报告里的总节拍（差 < 1 毫秒）。
两个数只要能分开，"看着在动"就成了另一套故事。

### 识别实况页（评委最可能追问的那一环）

工作台右上角有个 **「识别实况 →」**，也可以直接开 **http://127.0.0.1:8765/recognition**。

这一页只回答一个问题：**你怎么知道识别是对的。**

左半边是七个环节的中间图，点哪一格就换哪一格：

```
01 原图 → 02 V 通道 → 03 Otsu 阈值 → 04 形态学 → 05 外轮廓 → 06 抽稀 → 07 判定
```

**七张图全部是 `detect.py` 里那些函数现算的**，不是照着结果补画的。图下面直接
显示这一步对应的**真实源码**（从磁盘现读，带行号），并高亮正在执行的那一行。

右半边是逐件判定链，点 01~12 任意一件，能看到它完整的推理过程：

| 看什么 | 说明 |
|---|---|
| 真值 vs 判定 | 合成图有真值，一眼看出对没对 |
| **圆度对比** | 未抽稀 vs 抽稀后，旁边标着三个形状的理论值。正方形会从 0.71 跳到 0.785——**这就是"先修测量再谈阈值"那把尺子** |
| 形状打分 | 与三种形状理论圆度的距离，取最小，附顶点数是否落在区间 |
| 颜色 | 色相带上看峰值落在哪，红色为什么不能求均值，一眼就明白 |
| 坐标链 | 像素 → 托盘 mm → 整机 mm，三个数连着走 |

底下还有**判据滑块**：把置信度下限从 0.55 拉到 0.95，会看到 5 件立刻变成
"不抓"、顶部多出一个橙色「跳过 5 件」，而每件都写清了原因
（`置信度 0.87 < 0.95`）。**这就是"宁可不抓也不抓错"那条分支的现场证据**，
不是嘴上说的。

> ⚠️ 这一页的真值来自合成场景。它证明的是**换算链路和判定逻辑没写错**
> （自洽性检验），**不能当成果真机精度**。页面上也是这么写的。

## 2. 演示：不打开网页时，两条命令

### 命令 A —— 生成汇报材料

```powershell
python -m sorting.app.demo
```

屏幕上会打印：

```
  视觉    检出 12/12　分类全对 12/12　定位误差 均 0.31 / 最大 0.40 mm
  排程    12 件 1×2 6×2 4×2 2×2 3×2 5×2
  路径    3576 mm -> 3364 mm （5.9% ↓，策略 nn）
  节拍    50.8 s（解析估算，含回零）  入盒 12 / 跳过 0
  产物    out\demo
```

然后去 **`D:\智能分拣\out\demo\`** 打开这几个文件：

| 文件 | 是什么 | 汇报时用在哪 |
|---|---|---|
| `01_tray.png` | 合成托盘原图，12 件货随机摆 | 讲"输入长什么样" |
| `02_detect.png` | 检测结果，每件框出来并标了类别 | 讲识别 |
| `03_layout.png` | 排程路径图，绿线空驶、彩线搬运 | 讲"为什么排序能省路" |
| `report.md` | 完整报告，**每个数字都标了来源** | 直接当附录 |
| `timing.csv` / `trace.csv` | 原始数据，Excel 能开 | 要画自己的图时用 |

`report.md` 第 0 节最重要——它明说了哪些数字能当实测、哪些不能：

```
| 检出/分类/定位误差   | 合成托盘图跑真实检测代码  | ❌ 不能代替真机精度 |
| 节拍、步数、行程     | 按齿轮传动公式解析估算    | ❌ 不含加减速、回程间隙 |
| 排序前后的行走距离   | 由坐标直接算              | ✅ 真几何量，与硬件无关 |
| 屏幕帧               | 真实渲染出的 PNG          | ✅ 与真机同一份代码 |
```

### 命令 B —— 跑一遍完整流程（能看见机器"一件一件动"）

```powershell
python -m sorting.app.main --demo
```

打印：

```
检出 12 件，队列 12 件，策略 nn，估算行走 3364 mm
  #01 红色圆形 -> 1  3.7s
  #02 蓝色三角 -> 6  3.3s
  ...
  #12 红色方形 -> 2  4.6s
完成：12 件入盒，0 件跳过，总时长 50.8 s
[完成] 12/12 红色方形  进度 12/12
```

每一行就是一件货：**序号 → 类别 → 进几号盒 → 花了几秒**。
这是真机跑起来时会看到的同一条流程，只是把 STM32 换成了模拟器。

## 4. 演示"抓空了怎么办"

赛规下卡住一件会丢掉整轮，所以必须有失败分支。这条命令人为让第 2、5 件空夹：

```powershell
python -m sorting.app.main --demo --inject-skip 2 5
```

```
  #02 蓝色三角 -> NG（空夹，跳过）  2.1s
  ...
完成：10 件入盒，2 件跳过，总时长 48.1 s
```

注意两点，正是设计上要的效果：
- 空夹的件**不往料盒跑**，浪费的时间更少（2.1 s vs 正常 3.3 s）
- **机器没停**，继续做剩下的件

## 5. 调参数看效果（不改代码）

所有机械数值在 `sorting\config\machine.toml`，识别判据在
`sorting\config\classes.json`。复制一份改，用 `--config` 指过去：

```powershell
copy sorting\config\machine.toml out\试试.toml
notepad out\试试.toml          # 把 [axis.z] 的 speed_mm_s 从 100 改成 200
python -m sorting.app.demo --config out\试试.toml --out out\试试
```

节拍会从 **50.8 s 变成 41.3 s**——因为 Z 轴是瓶颈（占 45% 的时间）。

> `out\` 是 .gitignore 里的，改坏了删掉就行，不会污染仓库。

## 7. 真机怎么跑（等硬件到位）

现在还没有板子和相机，这条暂时跑不了，先记着形状：

```powershell
python -m sorting.app.main --port COM3 --image tray.png --calib calib.json
```

- `--port COM3`：接 STM32 的串口；不给就用模拟 MCU
- `--image tray.png`：用存好的照片代替相机；也可以用 `--camera 0` 直接开相机
- `--calib calib.json`：标定文件，**不给会直接报错退出**，因为像素换毫米必须靠它

标定文件这样生成（要先有真照片）：

```powershell
python -m sorting.tools.calibrate intrinsics --images 棋盘格\*.jpg -o intrinsics.json
python -m sorting.tools.calibrate tray --image 空托盘.jpg --intrinsics intrinsics.json -o calib.json
python -m sorting.tools.calibrate check --calib calib.json --image 空托盘.jpg -o check.png
```

`check.png` 打开看绿网格是否贴合托盘边缘——这是唯一能判断"点得对不对"的办法。

接真机时想边跑边看，用工作台那条：

```powershell
python -m sorting.app.studio --serial COM3
```

页面顶部徽标会从「仿真」变成「实机」，动画跟着真实回传的进度走。
**仿真和实机用的是同一套页面、同一个数据结构**，所以"演示时看到的"和
"实机上发生的"不会变成两套说法。

## 8. 放到公网上（已部署）

除了本机跑，还有一份常驻在服务器上，**发个链接别人就能看**：

| 页面 | 地址 |
|---|---|
| 工作台 | **https://jiangbot.com/sort/** |
| 识别实况 | **https://jiangbot.com/sort/recognition** |

手机上也能开（页面是响应式的，只是图会小一点）。看的人不需要装任何东西、
不需要连你的电脑，也不需要你的电脑开着。

**它是同一份代码**：服务器上跑的就是 `python -m sorting.app.studio --base /sort`，
和你在本地敲的那条命令只差一个前缀参数。

改了代码要同步上去，一条命令：

```powershell
bash scripts/deploy-demo.sh
```

脚本会打包 → 传上去 → 重启服务 → 跑一次 `--selftest` → 再试一下公网能不能打开。
任何一步失败都会停。

> ⚠️ 服务器上那份是**只读演示**：看的人能拖时间轴、点识别实况、拉判据滑块、
> 点「实跑一轮」（跑的是模拟 MCU），但**接不了真机**——串口在你自己那台电脑上。

<details>
<summary>服务器那边是怎么配起来的（换台机器时照这个来）</summary>

```bash
sudo mkdir -p /opt/sorting-demo && sudo chown ubuntu:ubuntu /opt/sorting-demo
sudo apt install -y python3.12-venv fonts-noto-cjk     # 字体必须有，否则屏幕帧上的中文是方框
cd /opt/sorting-demo && python3 -m venv venv
./venv/bin/pip install numpy opencv-python-headless pillow pyserial
```

systemd 单元 `/etc/systemd/system/sorting-demo.service`：

```ini
[Unit]
Description=Smart sorting workbench
After=network-online.target
Wants=network-online.target

[Service]
User=ubuntu
WorkingDirectory=/opt/sorting-demo
ExecStart=/opt/sorting-demo/venv/bin/python -m sorting.app.studio \
          --no-browser --host 127.0.0.1 --http-port 3030 --base /sort
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

隧道（cloudflared）在 `jiangbot.com` 那条主机规则**之前**插一条路径规则，
让 `/sort/*` 走工作台、其余照旧走原来的站点：

```yaml
  - hostname: jiangbot.com
    path: ^/sort(/.*)?$
    service: http://127.0.0.1:3030
```

改完 `sudo cloudflared tunnel ingress validate` 再 `sudo systemctl restart cloudflared`。

**为什么要 `--base`**：页面里的接口地址全写成相对路径（`api/scene`，不是
`/api/scene`），所以剥掉前缀以后，同一份 HTML 在 `/` 和 `/sort/` 下都能用。
有一条测试（`test_pages_use_relative_urls`）专门盯着别写回绝对路径——
写回去以后在子路径下就全 404，而且很难查。

</details>

## 常见问题

**Q：`python` 报不是内部或外部命令**
A：Python 没装或没加 PATH。装的时候勾 `Add python.exe to PATH`。

**Q：中文显示成乱码 / 报 `UnicodeEncodeError`**
A：程序里已经处理了（会强制 UTF-8 输出）。如果还乱，先执行
`$env:PYTHONIOENCODING='utf-8'` 再跑。

**Q：`out\demo` 里没有文件**
A：命令必须**在 `D:\智能分拣` 目录下**执行，路径是相对的。

**Q：节拍 50.8 秒，是不是真机能跑这么快**
A：**不是。** 这是按齿轮传动公式算出来的解析值，不含加减速、回程间隙、
相机曝光。报告里有 ⚠ 标注，实测值要等装配完把 `machine.toml` 的
`[meta] calibrated` 改成 `true` 才算数。

**Q：工作台打不开，或提示端口被占用**
A：先确认命令窗口没关（关掉窗口服务就停了）。端口冲突就换一个：
`python -m sorting.app.studio --http-port 8766`，浏览器开 `127.0.0.1:8766`。

**Q：工作台能不能给别人看？**
A：默认只绑本机，**只有这台电脑能开**。要让同一局域网里的手机/别的电脑看，
加 `--host 0.0.0.0`，然后开 `http://这台电脑的IP:8765`。

**Q：工作台的数据是不是为了好看单独造的？**
A：不是。托盘动画来自 `RecordingLink` 录下的真实运动时间轴，屏幕帧来自
`display/renderer.py` 的同一份渲染代码，原理栏里是运行时的真实中间量。
`--selftest` 会断言动画总时长和报告节拍相差小于 1 毫秒。
