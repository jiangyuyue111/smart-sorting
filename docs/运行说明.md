## 1. 演示：只需要记住两条命令

### 命令 A —— 生成汇报材料

```powershell
python -m sorting.app.demo
```

屏幕上会打印：

```
  视觉    检出 12/12　分类全对 12/12　定位误差 均 0.31 / 最大 0.40 mm
  排程    12 件 1×2 6×2 4×2 2×2 3×2 5×2
  路径    3576 mm -> 3364 mm （5.9% ↓，策略 nn）
  节拍    50.8 s（解析估算，含回零）  入盒 12 / 跳过 0
  产物    out\demo
```

然后去 **`D:\智能分拣\out\demo\`** 打开这几个文件：

| 文件 | 是什么 | 汇报时用在哪 |
|---|---|---|
| `01_tray.png` | 合成托盘原图，12 件货随机摆 | 讲"输入长什么样" |
| `02_detect.png` | 检测结果，每件框出来并标了类别 | 讲识别 |
| `03_layout.png` | 排程路径图，绿线空驶、彩线搬运 | 讲"为什么排序能省路" |
| `report.md` | 完整报告，**每个数字都标了来源** | 直接当附录 |
| `timing.csv` / `trace.csv` | 原始数据，Excel 能开 | 要画自己的图时用 |

`report.md` 第 0 节最重要——它明说了哪些数字能当实测、哪些不能：

```
| 检出/分类/定位误差   | 合成托盘图跑真实检测代码  | ❌ 不能代替真机精度 |
| 节拍、步数、行程     | 按齿轮传动公式解析估算    | ❌ 不含加减速、回程间隙 |
| 排序前后的行走距离   | 由坐标直接算              | ✅ 真几何量，与硬件无关 |
| 屏幕帧               | 真实渲染出的 PNG          | ✅ 与真机同一份代码 |
```

### 命令 B —— 跑一遍完整流程（能看见机器"一件一件动"）

```powershell
python -m sorting.app.main --demo
```

打印：

```
检出 12 件，队列 12 件，策略 nn，估算行走 3364 mm
  #01 红色圆形 -> 1  3.7s
  #02 蓝色三角 -> 6  3.3s
  ...
  #12 红色方形 -> 2  4.6s
完成：12 件入盒，0 件跳过，总时长 50.8 s
[完成] 12/12 红色方形  进度 12/12
```

每一行就是一件货：**序号 → 类别 → 进几号盒 → 花了几秒**。
这是真机跑起来时会看到的同一条流程，只是把 STM32 换成了模拟器。

## 2. 想看屏幕长什么样

屏幕是赛规硬性计分项（序号/名称/图片/总数，每件刷新），所以要能拿出来看：

```powershell
python -m sorting.app.main --demo --frames out\frames
```

打开 **`D:\智能分拣\out\frames\`**，26 张 PNG，每件两张：

```
001_ready.png     开跑前
002_moving.png    #01 搬运中
003_placed.png    #01 已入盒
...
```

`*_moving` 和 `*_placed` 一对一对看，就是"每分拣一件刷新一次"的效果。
尺寸 480×320，和真机上那块屏同分辨率、同一份渲染代码。

## 3. 演示"抓空了怎么办"

赛规下卡住一件会丢掉整轮，所以必须有失败分支。这条命令人为让第 2、5 件空夹：

```powershell
python -m sorting.app.main --demo --inject-skip 2 5
```

```
  #02 蓝色三角 -> NG（空夹，跳过）  2.1s
  ...
完成：10 件入盒，2 件跳过，总时长 48.1 s
```

注意两点，正是设计上要的效果：
- 空夹的件**不往料盒跑**，浪费的时间更少（2.1 s vs 正常 3.3 s）
- **机器没停**，继续做剩下的件

## 4. 调参数看效果（不改代码）

所有机械数值在 `sorting\config\machine.toml`，识别判据在
`sorting\config\classes.json`。复制一份改，用 `--config` 指过去：

```powershell
copy sorting\config\machine.toml out\试试.toml
notepad out\试试.toml          # 把 [axis.z] 的 speed_mm_s 从 100 改成 200
python -m sorting.app.demo --config out\试试.toml --out out\试试
```

节拍会从 **50.8 s 变成 41.3 s**——因为 Z 轴是瓶颈（占 45% 的时间）。

> `out\` 是 .gitignore 里的，改坏了删掉就行，不会污染仓库。

## 6. 真机怎么跑（等硬件到位）

现在还没有板子和相机，这条暂时跑不了，先记着形状：

```powershell
python -m sorting.app.main --port COM3 --image tray.png --calib calib.json
```

- `--port COM3`：接 STM32 的串口；不给就用模拟 MCU
- `--image tray.png`：用存好的照片代替相机；也可以用 `--camera 0` 直接开相机
- `--calib calib.json`：标定文件，**不给会直接报错退出**，因为像素换毫米必须靠它

标定文件这样生成（要先有真照片）：

```powershell
python -m sorting.tools.calibrate intrinsics --images 棋盘格\*.jpg -o intrinsics.json
python -m sorting.tools.calibrate tray --image 空托盘.jpg --intrinsics intrinsics.json -o calib.json
python -m sorting.tools.calibrate check --calib calib.json --image 空托盘.jpg -o check.png
```

`check.png` 打开看绿网格是否贴合托盘边缘——这是唯一能判断"点得对不对"的办法。

## 常见问题

**Q：`python` 报不是内部或外部命令**
A：Python 没装或没加 PATH。装的时候勾 `Add python.exe to PATH`。

**Q：中文显示成乱码 / 报 `UnicodeEncodeError`**
A：程序里已经处理了（会强制 UTF-8 输出）。如果还乱，先执行
`$env:PYTHONIOENCODING='utf-8'` 再跑。

**Q：`out\demo` 里没有文件**
A：命令必须**在 `D:\智能分拣` 目录下**执行，路径是相对的。

**Q：节拍 50.8 秒，是不是真机能跑这么快**
A：**不是。** 这是按齿轮传动公式算出来的解析值，不含加减速、回程间隙、
相机曝光。报告里有 ⚠ 标注，实测值要等装配完把 `machine.toml` 的
`[meta] calibrated` 改成 `true` 才算数。
