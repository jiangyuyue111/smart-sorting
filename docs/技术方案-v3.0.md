# 智能分拣装置 · 技术实现方案 v3.0

> 2027 工创赛「智能+」赛道 · 智能分拣赛项
> 目标：**初赛**（不设决赛路径）
> 日期：2026-10-20

---

## 0. 一页纸

**做什么**：一台 350×350×450mm 以内的自动分拣装置。赛前由组委会抽签决定货物组合（≥12 件、6 类），随机倒入托盘；装置自行识别、按「形状+颜色」聚类、逐件抓取入盒，并在机载屏上逐件显示分拣信息。

**技术路线一句话**：
> SG2002 跑 Linux + TPU 识别 → 待机时一次拍盘得出全部任务 → STM32 驱动三轴龙门 + 真空吸盘开环执行 → 每件分拣后刷新 framebuffer 表格。

**三条定盘决策**：

| 决策 | 结论 | 依据 |
|---|---|---|
| 识别 | **经典 CV 为主，YOLO on TPU 为可切换备通道** | 两者基础设施都已具备，切换成本≈0 |
| 系统 | **AKA-00 Linux (Buildroot)**，StarryOS 作备胎 | 相机 10ms vs 131–255ms，实测 |
| 范围 | **砍掉开放集**：不聚类未知品类、不做决赛适配 | 只打初赛 + 物料自备 |

## 1. 规则 → 工程指标

| 规则原文 | 工程指标 |
|---|---|
| 每轮调试 3 分钟、运行 3 分钟 | 总预算 **180 s** |
| 不少于 12 件、6 种类别 | 6 类 × 2 件 = 12 件，平均 **15 s/件** |
| 15 秒没有任何动作即本轮结束 | **无动作看门狗 ≤ 5 s**（见 §8） |
| 形状相同**且**颜色相同才可同盒 | 输出「类别编号」，不是「名称置信度」 |
| 同形同色多件每件 5 分，必须全部入盒 | **每类必须 2 件全中**，部分入盒得 0 |
| 不同形状或颜色混入同盒 → 该盒不得分 | **错 1 件最多毁 2 类 20 分** |
| 正确显示序号/名称/图片/总数，每条 2 分 | 显示模块独立看护，逐件刷新 |
| 分拣信息未显示就抓下一件 → 不得分 | 显示必须先于下一件动作 |
| 一键启动后再接触（含笔记本）→ 结束 | 全自动，无交互、无遥控 |
| 掉落在装置范围内/外 → 结束 | 真空压力闭环，绝不带着未吸牢的件移动 |
| 成绩 P = A×20% + B×10% + C×70% | A+B 是 30 分的绝对保底 |

**满分 60 分**（12 件 × 5）。C 为相对分：C = 100 × 本队得分 ÷ 最高得分。

## 2. 系统架构

```
┌─────────────────────────────────────────────────────────┐
│  SG2002 / AKA-00 Linux (Buildroot)  — Python 3.11        │
│                                                          │
│  ┌─────────┐   ┌──────────┐   ┌──────────┐  ┌────────┐  │
│  │ 采图    │→ │ 识别     │→ │ 任务队列  │→ │ 显示   │  │
│  │ UVC     │   │ CV/YOLO  │   │ 状态机    │  │ fb0    │  │
│  └─────────┘   └──────────┘   └────┬─────┘  └────────┘  │
│                                     │ 心跳看门狗         │
└─────────────────────────────────────┼────────────────────┘
                                      │ UART
                              ┌───────▼────────┐
                              │  STM32F407     │
                              │  三轴步进脉冲   │
                              │  加减速规划     │
                              └───────┬────────┘
                                      │ STEP/DIR
                          ┌───────────▼─────────────┐
                          │ 龙门 XY + Z + 真空吸盘   │
                          └─────────────────────────┘

              ┌──────────────────────────┐
              │ MIPI-DSI 5" 屏 (480×854) │  ← framebuffer
              └──────────────────────────┘
```

**分层原则**：
- SG2002 只做「决策」，STM32 只做「脉冲」。任何实时性要求都不落在 Linux 上。
- 显示、看门狗、相机监控各自独立，**不被运动阻塞**。

## 4. 机械

### 4.1 包络
- 整机 **≤ 350 × 350 × 450 mm**（硬上限，检录不过不能参赛）
- 托盘 **≥ 160 × 160 mm**，边缘高度 ≥ 10 mm
- 6 个独立储物盒，标注 1–6，每盒 ≤ 4 件

### 4.2 唯一的硬约束：X 向行程
```
吸盘尖点：最左盒心 (x≈142) → 托盘最右取件点 (x≈415)
需求行程 = 273 mm
横梁上限 350mm，扣掉 Z 滑座后可用 ≈ 290 mm
余量 ≈ 17 mm  ← 全吃在结构公差里
```
**CAD 顺序必须是"先定盒体能做多小，再反推横梁"**，反过来一定超。
盒子外宽压到 84mm（内腔约 80mm）是当前极限；若装不下 4 件 40mm 货物，退路是盒区横向排布或可旋转盒盘。

### 4.3 Z 轴
- 行程压到**刚好够吸起最高件 + 5mm**，不要留富余
- 目标速度 **40–50 mm/s**（每件要升降 4 趟，Z 是节拍瓶颈）
- 到位后 **静置 ≥ 100ms 再吸**（惯性未停就吸会吸偏）

### 4.4 光学
- 镜头焦距需**复核**：若传感器为 1/3"，6mm 镜头在 WD 250mm 处即可覆盖 200mm 视场，畸变远小于 3.6mm 广角
- 相机视场 ≈ 200mm（覆盖 160mm 托盘 + 余量）
- **加遮光罩 + 固定 LED 环光**：把场地光照变量物理消除，这是 CV 路线成立的前提

## 5. 物料设计（自备）

物料由本队制作，因此可以主动优化识别难度。**这是本方案最大的降本点。**

### 5.1 形状（同时满足两个约束）

| 约束 | 要求 |
|---|---|
| 视觉 | 俯视投影互不撞车 |
| 机械 | 顶面是平面（吸盘只能吸平面） |

**候选集**：正方体、长方体、正三棱柱、正四棱柱、正五棱柱、正六棱柱、圆台 —— 任选 6 个。

**必须避开的撞车组合**（同色时俯视无法区分）：

| 组合 | 原因 |
|---|---|
| 球 ↔ 圆柱（立放） | 投影都是圆 |
| 正方体 ↔ 四棱柱（立放） | 投影都是正方形 |
| 正四面体（立放） ↔ 正三棱柱（立放） | 投影都是三角形 |

**球、圆锥直接排除**：吸盘吸不住。

### 5.2 颜色
- 选在色环上**角度间隔大**的 6 个色相，判据用色相角度距离 `min(|Δh|, 360-|Δh|)`
- **不用 RGB 欧氏距离**（红和橙在 RGB 里很近）
- 避免红/橙、蓝/紫这类近邻组合

### 5.3 工艺
- **哑光表面**（磨砂或喷哑光漆）——消除镜面高光，这是颜色分割最大的干扰源
- **等高、平顶**——Z 轴行程变常数，节拍稳定
- 尺寸 ≤ 40mm 见方
- 表面按要求附**模拟污渍/缺陷的图形、文字、二维码**（规则强制）

### 5.4 关于二维码
**不做识别。** 理由：640×480 下 8mm 二维码仅约 26 px，不可解。且它不是分拣判据。
表面仍按规则印上，但只作为**颜色统计的噪声源**处理（见 §6.2）。

## 6. 视觉与识别

### 6.1 采图

| 项 | 值 |
|---|---|
| 分辨率 | 640 × 480（相机驱动固定） |
| 视场 | ≈ 200 mm → **3.2 px/mm** |
| 单件 40mm | **≈ 128 px** |
| 取帧耗时 | **~10 ms**（Linux 实测） |

**拍照时机：待机阶段，一次拍完整盘。**
- 不占 15 秒节拍
- 相机若挂死，还有时间重启（一旦开赛卡住就归零）
- 整轮只需要 **1 次识别**

### 6.2 主通道：经典 CV

```
单帧 YUYV
  ↓ 转 BGR
  ↓ 背景分割（单色托盘，固定阈值；有遮光罩后阈值稳定）
  ↓ 形态学开闭去噪
  ↓ 距离变换 + 分水岭  ← 处理件挨件粘连
  ↓ 每个连通域
       ├─ 顶点数（多边形逼近）
       ├─ 圆度 = 4πA/P²
       ├─ 填充率 = 面积 / 外接矩面积
       ├─ 长宽比
       └─ HSV 主色【中位数】
  ↓ 与 6 类标定特征近邻匹配
  ↓ 类别编号 + 质心（不是外接框中心）
```

**三个关键实现细节**：

1. **颜色取中位数，不取均值。**
   规则要求在货物表面加模拟污渍、文字、二维码——这些都是高对比斑块，会把均值拖偏。中位数抗污染。
   更好的是先做**形态学开运算**或用**局部方差图**掩掉高纹理区，再统计颜色。

2. **不用外接框中心。**
   四面体、五棱柱这类不规则件的 bbox 中心 ≠ 形心。用 **轮廓质心** 或 **最小外接矩中心**。

3. **多特征投票，不赌单一特征。**
   顶点数最不可靠（模糊、污渍、透视都会改它）。圆度和填充率更稳。三特征投票，多数为准。

**切换条件**：以下任意一条成立，转 YOLO 通道——
- 同色两形状怎么调阈值都分不开
- 场地光照无法用遮光罩控制
- 粘连严重到分水岭拆不开

### 6.3 备通道：YOLO on TPU

基础设施已全部就绪，**切换成本接近零**：

| 项 | 现状 |
|---|---|
| 模型转换 | 训练 → ONNX → cvimodel，流程见 `YOLO_BUILD_FULL.md` |
| 运行时 | `libcviruntime` + `libcvikernel`，四语言均已跑通 |
| 推理耗时 | **40 ms**（与 OS 无关，实测） |
| 端到端 | 174 ms / 5.7 fps（Linux 实测） |
| 类别数 | 改为 6，重训即可 |

**风险控制不靠模型，靠门限**：`conf` 阈值之上仍要求与 CV 通道结论一致；不一致 → 跳过该件。

### 6.4 标定
1. 相机内参标定 + 去畸变（若用广角镜头，**必须先去畸变再做仿射**，仿射消不掉径向畸变）
2. 像素 → 机械坐标仿射变换
3. 6 类特征表：每类拍 10–20 张，记录特征均值与容忍半径

## 7. 运动控制

### 7.1 分工
- **SG2002**：算坐标、排任务、发指令、看门狗
- **STM32F407**：收指令 → 规划加减速 → 定时器出 STEP/DIR

### 7.2 通信
沿用已验证的 UART 帧协议（SOF + CMD + LEN + PAYLOAD + CHK），超时 500 ms。
指令集只需四条：

```
MOVE  x,y,z,speed      绝对定位，带加减速
WAIT  timeout          到位等待
VAC   on|off           真空泵
STATUS                 返回压力开关状态 + 当前位置
```

### 7.3 关键动作序列（单件）

```
1. MOVE 到取件点上方
2. MOVE Z 下降到位
3. WAIT 120ms（停稳）
4. VAC on → 等压力开关达标（≤1.5s，不达标 → 原地重吸，最多 2 次）
5. MOVE Z 上升
6. MOVE 到目标盒上方
7. MOVE Z 下降
8. VAC off + 破真空
9. MOVE Z 上升
10. 刷新显示（必须在本件抓取下一件之前完成）
```

**失败处理**：第 4 步压力始终不达标 → 放弃该件，**立即转向下一件**（继续运动=保活），不重跑 XY。

## 8. 任务调度与看门狗

### 8.1 任务队列
待机时一次生成，按「类别分组 + 组内按距离排序」：

```
类别1: [件A(x,y), 件B(x,y)]  → 盒 1
类别2: [件C, 件D]            → 盒 2
...
```

**排序原则**：同一类的两件连着做（避免盒子重复定位），组间按最近邻排序。

### 8.2 无动作看门狗（关键）

规则：**15 秒没有任何动作 → 本轮结束**。这不是每件的时间配额，而是"完全静止"的判死线。

| 场景 | 风险 | 对策 |
|---|---|---|
| 视觉在算 | 机械不动 | **拍照与识别全部放在待机阶段**，开赛后不再做识别 |
| 串口等回复 | 不动 | 所有等待设上限，超时立即发下一条指令 |
| 程序判不出来 | 不动 | 判不出来 → 跳过 → **立刻去下一件** |
| 相机挂死 | 不动 | 不依赖开赛后取图；另有进程级看门狗 |

**心跳规则**：任意 5 秒内没有发出运动指令 → 触发保活动作（Z 轴微抬或转向下一件）。

### 8.3 决策红线

> **宁可少分一类（丢 10 分），不要放错一盒（最多毁 20 分）。**

任何一处不确定，一律跳过。

## 9. 显示

### 9.1 硬性要求
- 必须是**仅具有显示功能**的高亮显示屏（不能有触摸交互，否则可能被认定为遥控）
- 必须显示：**序号、货物名称、货物图片、分拣成功总数量**
- 任一条错误 → 该条 2 分不得
- **必须先刷新，再抓下一件**

### 9.2 实现
- 目标设备 `/dev/fb0`，分辨率 480×854
- 首行标题，其下逐行追加记录
- **货物图片 = 从待机时拍的那张盘图里裁出的缩略图**（不建图片库，永远与实物一致）
- 刷新时机：每件入盒完成后立即刷新，刷新完成才发下一条运动指令

### 9.3 待验证
`fbpattern` / 开机 logo 只证明内核级绘图正常，**用户态写 `/dev/fb0` 尚未验证**。
这是目前唯一没有实测背书的环节，优先级最高。

## 10. 节拍预算

| 步骤 | 估算 |
|---|---|
| XY 到取件点（300mm @ 200mm/s） | 1.8 s |
| Z 下降（40mm @ 40mm/s） | 1.0 s |
| 停稳 + 抽真空确认 | 1.2 s |
| Z 上升 | 1.0 s |
| XY 到盒子（200mm） | 1.2 s |
| Z 下降 | 1.0 s |
| 破真空释放 | 0.3 s |
| Z 上升 | 1.0 s |
| 显示刷新 | 0.2 s |
| **单件合计** | **≈ 8.7 s** |

12 件 ≈ **105 s**，占 180 s 预算的 58%，**留出约 75 s 容错**。

> 单件允许超过 15 s（只要不停），但要守住总量 180 s。

## 11. 风险与兜底

| 风险 | 检测方式 | 兜底动作 |
|---|---|---|
| 相机 DMA 挂死 | 只在待机取图，开赛不依赖 | 开赛前重启进程 |
| 吸盘吸空 | 压力开关 | 原地重吸 ≤2 次 → 跳过该件 |
| 真空泵失效 | 压力始终不达标 | 跳过，继续后续动作保活 |
| 识别置信度低 | 特征距离 > 容忍半径 | 跳过该件 |
| 越界/撞限位 | TMC2209 StallGuard | 立即停机并回零 |
| 串口无响应 | 500ms 超时 | 重发 ≤2 次 → 进入安全态 |
| 显示异常 | 刷新后自检 | 仍继续分拣（分拣分优先于显示分） |
| 放置时掉落 | — | **规则直接结束本轮**，因此 Z 轴到盒内才破真空，且破真空后先抬 Z 再移动 |

## 附录 A：为什么不用 StarryOS 作为主路径

| | AKA-00 Linux | StarryOS |
|---|---|---|
| 相机取帧 | **~10 ms** | 131–255 ms |
| 端到端 | **174 ms / 5.7 fps** | ~481 ms / 2.1 fps |
| TPU Forward | 40 ms | 40 ms |

TPU 性能与 OS 无关；**差距 100% 来自 USB UVC 驱动成熟度**。

StarryOS 的价值不在交付，而在两点：
1. **备胎**——Linux 验证若出问题，那条路是通的
2. **B 项创新性素材**——内核适配、CVI 相机驱动、TPU 打通都是真实工作，可写入作品说明（但**不要声称分拣装置运行在 StarryOS 上**）

| 状态机结构 | 按时间戳推进，整段动作期间**不阻塞主循环**，照常取帧/推理/打日志 |
| 防单帧误检 | 连续 N 帧满足条件才执行（对应本方案的置信度门控） |
| 相位裕度 | 不在运动中途连续修正；一帧延迟会叠加成振荡 |
| 帧率补偿 | 所有按时间开口的环，按实测帧率重标一次 |

**不可借鉴**：相机接口（StarryOS 专有 ioctl），以及全部调参常量（网球车专属）。
