## 🔴 先说边界

**本目录只放「调研结论和文档」，不放「平台源码」。**

那套平台的代码**不是开源的**，理由有三条，任何一条单独就足够：

1. **两个主仓库都没有 LICENSE 文件** → 默认「保留所有权利」，著作权属原作者
2. 内部嵌套了 **AGPL-3.0**（Ultralytics YOLOv11）和 **GPL-3.0**（PyQt5）—— 两者都有传染性
3. 以及海康 / 大恒 / 越疆 / NVIDIA 的**专有 SDK**（明确禁止再分发）

| | |
|---|---|
| ✅ **可以** | 读它、跑它、学它的**架构思路**、照着思路写我们自己的实现、查 SDK 官方文档 |
| ❌ **不可以** | 把它的代码拷进我们的项目 / 参赛作品 / **本仓库** |

> ⚠️ **即使这个仓库是私有的，把别人的代码拷进来也属于「向第三方分发」**，不在许可范围内。
> 同理：**用 SDK 开发合法，"把 SDK 拷进自己仓库再发布"不合法。** 要用就去厂商官网免费下载。

## 一句话结论

这台机器**不是**"可以扒固件二次开发的商业盒子"，而是**一台装着别人写的机器视觉教学平台的 Jetson 开发套件** ——
**代码不可复用**，但**硬件可以借来当开发验证平台**，**架构思路值得学**。

## 给组员的四条要点

1. **代码只能读，不能抄** —— 尤其是 `MAIN_Calibrate.py`（手眼标定）和 PyQt5 那套界面结构，读思路，自己重写。
2. **相机那套东西我们已经实测跑通了** —— 大恒 MER2-302-56U3C，2048×1536 @ 48.2fps。但它 **¥2000+，且全局快门在我们的固定俯视场景没有优势**，不建议买。
3. **Jetson 只能当「开发验证平台」借来用** —— 它和我们的主控树莓派同为 aarch64 + Python，代码能双向搬。
   但 ⚠️ **必须纯 OpenCV + NumPy**：一旦 `import torch` / 用 CUDA / TensorRT，代码就搬不回 Pi 了。
4. **不要为了「用上这块算力」而改成 YOLO** —— "决赛现场换货要能现场调阈值" 这个选经典 CV 的理由依然成立。
