## 一、相机专题：USB3 Vision 工业相机

### 1.1 ★ 它不是 UVC —— 这是最容易踩的坑

**实测确认**：那台机器上 `/dev/video*` **一个节点都没有**，`lsmod` 里也没有 `uvcvideo`。

> **USB3 Vision / GigE Vision 工业相机不走 UVC 协议**，所以 **`cv2.VideoCapture()` 读不到它**。
> 必须用厂商 SDK（`gxipy`）或开源库 **Aravis** 才能取图。

**❌ 错误直觉**：`lsusb -t` 里 `Driver=` 是空的 → "驱动没装，要编译安装"
**✅ 实际**：**U3V 走 usbfs 用户态，压根没有内核驱动**，没有东西需要编译。`Driver=` 空是**正确现象**。

> 💡 **可复用的判断力**：「系统里缺某个模块 / 设备节点」有时是**设计如此**，不是故障。
> 能区分这两者，能省掉一整轮无用排查。

### 1.2 三层结构（决定能不能移植）

| 层 | 文件 | 性质 | 可移植性 |
|---|---|---|---|
| Python 封装 | `gxipy/*.py` | **纯 Python + ctypes** | 代码跨架构 ✅，但**版权属大恒** ❌ |
| 原生库 | `libgxiapi.so` | 闭源二进制，**锁架构** | ❌ |
| 协议 | USB3 Vision + **GenICam** | **公开标准** | ✅ 可用开源实现 |

**换架构的正确做法不是"移植"**（闭源二进制无源码可移），而是**去官网下载对应架构的构建**：

| 板子 | 架构 | 结论 |
|---|---|---|
| 树莓派 3/4/5 | aarch64 | ✅ 大恒官网有 aarch64 构建 |
| SG2002（LicheeRV Nano） | RISC-V | ❌ 厂商无此构建，闭源无法自编译 —— **死路** |
| ESP32-S3 / P4 | Xtensa | ❌ MCU 跑不了 Linux 用户态 SDK |

**绕行方案**：**Aravis**（LGPL-2.1，实现 GigE Vision + USB3 Vision + GenICam）**能在任意 Linux 架构编译，含 RISC-V**。代价是自己写对接代码。

### 1.3 实测参数（大恒 MER2-302-56U3C）

| 项 | 值 |
|---|---|
| 分辨率 / 格式 | 2048×1536 / **BayerRG8**（彩色，需去马赛克）· 全局快门 |
| 实测帧率 | **48.2 fps**（连抓 30 帧 / 0.622s，标称 56） |
| 链路 | USB3 Vision，**5000 Mbps SuperSpeed**（掉到 480 就废） |
| 机身温度 | 39.2 °C |

### 1.4 ★ gxipy API 坑

```python
import gxipy as gx, cv2

dm = gx.DeviceManager()
n, dl = dm.update_device_list()      # ← 设备信息在这个 dl 里
cam = dm.open_device_by_index(1)

# ✅ 参数是「属性式」的
cam.ExposureAuto.set(0)              # 先关自动，再设值
cam.ExposureTime.set(20000.0)        # 单位 µs
print(cam.Gain.get(), cam.Width.get())

# ❌ 这不是 gxipy 的接口 —— 它会静默返回 None，不报错！
cam.get_int_feature_value("ExposureTime")     # → None
# ❌ U3VDevice 也没有这个方法，调用会 AttributeError
cam.get_device_info()

cam.stream_on()
raw = cam.data_stream[0].get_image()
arr = raw.convert("RGB").get_numpy_array()    # BayerRG8 必须走 convert 去马赛克
cv2.imwrite("f.jpg", cv2.cvtColor(arr, cv2.COLOR_RGB2BGR))
cam.stream_off(); cam.close_device()
```

> 💡 **API 返回 `None` 时，先怀疑自己用错接口，不要怀疑能力缺失。**
> **静默失败比报错更坑** —— 报错会告诉你路走错了，`None` 会让你以为硬件不支持。

## 二、可借鉴的架构（读思路，别抄代码）

1. **接口 + 工厂双模式** —— 上层完全不知道底层是哪家相机/哪个机械臂：

   ```
   interface/     CameraInterface (ABC): open/close/capture/is_open/get_last_error
   factory/       CameraType{HaiKang, DaHeng} → CamFactory.create_camera(type)
   implement/     DahengCam / haikangImpl 各写一份实现
   ```

   **换硬件不用改业务代码。** 两个目录加起来才 61 行，是全套架构的钥匙。

2. **用 dataclass 统一检测结果**：

   ```python
   @dataclass
   class Detection:
       bbox: ...; score: float; class_id: int; class_name: str; extra: dict
   ```
   后端可以是 PyTorch / ONNX / TensorRT / OpenVINO，**上层拿到的结构永远一样**。`extra` 留了 mask、关键点的扩展位。

3. **QThread + 信号槽做采集** —— 采集线程发信号给 UI 线程，界面不卡。
   （对照我们 SG2002 上遇到的"非阻塞读退化 / 相机挂死"，独立线程 + 阻塞采集正是常规解，值得对比研究。）

4. **手眼标定的工程实现**（`MAIN_Calibrate.py`，1248 行）—— 与我们分拣项目「内参去畸变 + 仿射」那步直接相关。
   ⚠️ **读思路，自己重写。**

5. **反面教材（读的时候要有分辨力）**：
   - `yolov11Impl.py` 与 `yolo11lmpl.py` **大小完全相同（7252 字节）** —— 文件名 `I`/`l` 打错后复制一份，没人清理
   - `requirements.txt` 里混着 `ubuntu-*`、`dbus-python` —— 是 `pip freeze` 抓进来的系统包，不是依赖
   - `wood_木板颜色和缺陷/` **不是 git 仓库**，没有版本管理

| 组件 | 许可 | 能不能用 |
|---|---|---|
| 平台自身代码（两个主仓库） | **无 LICENSE** = 保留所有权利 | ❌ 不能 |
| **Ultralytics YOLOv11** | **AGPL-3.0**（来自 Gitee 的 fork，fork 同样受限） | ❌ 传染：分发或联网提供服务即须整体开源 |

| 海康 `MvImport` / 越疆 `DobotDllPy` | 各家版权 | ❌ 不能分发 |
| `/opt/MVS`、Galaxy SDK | 专有（禁止再分发） | ❌ 不能分发；**官网可免费下载自用** ✅ |
| CUDA / cuDNN / TensorRT / VPI2 | NVIDIA EULA | ❌ 不能分发 |
| OpenCV | Apache-2.0 | ✅ |
| PyTorch / torchvision | BSD-3 | ✅ |
| `labelImg` | MIT | ✅ 去 `github.com/HumanSignal/labelImg` 拿 |

## 四、复用方法（工程技巧）

### 4.1 设备排查：banner 就是情报

只拿到一段 SSH 登录横幅也能定位机器：
`OpenSSH_8.2p1 Ubuntu-4ubuntu0.13` → 精确匹配 Ubuntu 20.04；hostname `ubuntu` = 出厂默认未改；
`minimized... unminimize` = Ubuntu 云镜像标准 MOTD。

**在本地网段扫 22 端口找机器**，比追问对方要 IP 快。

### 4.2 免密接入：专用密钥，密码不进聊天记录

生成一把**用途专用**的密钥 → 让对方在**他自己的会话**里粘一行 `authorized_keys` →
**密码全程不出现**，事后**删那一行即彻底失效**。

### 4.3 ★ 四层引号地狱的破解

`PowerShell → WSL bash → ssh → 远端 bash` 四层嵌套时，**把脚本写成文件再管道喂进去**：

```bash
tr -d '\r' < script.sh | ssh host 'bash -s'
```

彻底绕开所有嵌套转义，脚本里可以随便写引号、heredoc。

### 4.4 ★ 打包自己不完全了解的目录树：一律用白名单

**血泪教训**：第一次用 `tar --exclude=` 黑名单，跑到 **482MB 还没完**。根因两条：

- **`--exclude='runs'` 不生效** —— tar 的排除模式匹配的是**完整路径**，`runs` 匹配不到 `rub_yolov11/rubclassify/runs`，那 **229MB 训练输出全漏进来了**
- 还漏了目录里每张 **9MB 的 BMP** 数百张

改成白名单后一步降到 **6.3MB**：

```bash
find <dirs> -type f \( -name '*.py' -o -name '*.md' -o -name '*.yaml' ... \) \
  ! -path '*/.git/*' ! -path '*/__pycache__/*' > /tmp/packlist.txt
tar czf - -T /tmp/packlist.txt
```

> ⚠️ **注意**：`tar -T -`（从 stdin 读清单）**会和"脚本从 stdin 喂入"冲突** —— stdin 被抢了。
> 必须先把清单落到 `/tmp/list`，再 `-T /tmp/list`。

### 4.5 判断代码归属：只看三样硬证据

不看"有没有源码"（**有源码 ≠ 开源**）、不听"谁买了版权"（**买的是使用许可 ≠ 著作权**）、不看"能不能连上"。
只看客观的：**`.git` 的 remote + commit author + 有没有 LICENSE 文件**。

> **授权不会自动传递**：学校买到 → 学生个人 ≠ 自动获得 → 校外竞赛作品 ≠ 被覆盖。
