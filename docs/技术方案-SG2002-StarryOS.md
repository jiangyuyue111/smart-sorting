## 0　一页纸

```
┌──────────── SG2002 · StarryOS（非实时，只做视觉与决策）────────────┐
│ 采图→去畸变→分割→特征→匹配/分组→任务队列→状态机                   │
│ (待机1次，之后关相机)                                             │
└──────────────────────────────┬───────────────────────────────────┘
                               │ UART 921600 8N1 文本行（USB-TTL）
┌──────────────────────────────▼───────────────────────────────────┐
│ STM32F407（实时）                                                 │
│  3×TMC2209 脉冲 · 限位回零 · 压力开关 · 真空阀 · 硬件看门狗        │
│  ─────── SPI 25 MHz ───────▶  ST7796S 3.5" 480×320 IPS           │
└──────────────────────────────────────────────────────────────────┘
```

| 决策 | 理由 |
|---|---|
| **屏由 STM32 驱动，不由 SG2002 驱动** | StarryOS 没有 SPI 子系统且无人开发；见 §2 |
| 整盘一次成像，开赛后关相机 | 板子 UVC/DMA 有挂死史，不开就没有挂死的机会 |
| 心跳保活放在 STM32 | PC 进程死了 MCU 还在动，不会被 15 秒判死 |
| 串口走文本行协议 | 单件 8.7 s，带宽不是瓶颈；出问题串口日志直接看懂 |
| 不用 OpenCV，纯 Rust | 128 MB 内存下唯一能稳住的方案（§6.3 内存账） |

## 1　硬件与系统栈

| 层 | 选型 | 状态 |
|---|---|---|
| 主控 | LicheeRV Nano（SG2002，C906 + 1 TOPS NPU） | 已在手 |
| OS | StarryOS（tgoskits 生态） | 8 月已自行移植，相机 + TPU 跑通 |
| 内核驱动（用到的） | DWC2 主机栈（相机 + USB-TTL）、V4L2、SD | 已就绪 |
| 内核驱动（**不需要的**） | ~~SPI~~、~~GPIO~~、~~framebuffer~~ | **本方案不使用**（§2） |
| 应用语言 | Rust，`riscv64gc-unknown-linux-musl` | 工具链已打通 |
| 图像库 | `image` / `imageproc` | 生态可用 |
| 机载屏 | **ST7796S 3.5" 480×320 SPI IPS** | 由 STM32 驱动 |
| 下位机 | STM32F407（168 MHz，192 KB SRAM）+ 3×TMC2209 | 常规 |
| 执行 | 真空吸盘 + 隔膜泵 + 2×电磁阀 + 压力开关 | 常规 |

**关键结构性好处**：SG2002 上只用 **USB（相机）+ USB-TTL（串口）+ SD**，全部走已经验证过的 DWC2 主机栈。**整条链路不依赖任何尚未存在的内核驱动** —— 这正是原方案里最大的不确定性，现在归零了。

**为什么是 ST7796S 而不是 ILI9488**：ILI9488 在 SPI 模式下只接受 **18 位色**（`COLMOD=0x66`，3 字节/像素），一帧 480×320×3 = 460 KB；ST7796S 支持 **RGB565**（`COLMOD=0x55`），一帧 307 KB，而且和 ST7789 指令集同源。选错屏刷新慢 1.5 倍。

## 2　机载屏：为什么挂 STM32

### 2.1 三条路的取舍

StarryOS 在 SG2002 上没有 SPI 子系统，也没有人在做。选项只有三个：

| 路线 | 人日 | 可控性 | 结论 |
|---|---|---|---|
| 给 StarryOS 写 SPI 控制器驱动 + spidev | 5–10 | ❌ 内核开发，每改一行重烧卡 | 放弃 |
| GPIO 软件模拟 SPI | — | ❌ 480×320 必然刷不动 | 放弃 |
| **屏挂 STM32，SG2002 只发文本** | **5–6** | ✅ HAL 现成，SWD 在线调试 | **采用** |

第三条不只是"绕开"，它在几个点上反而更好：

| 好处 | 说明 |
|---|---|
| 不依赖任何未确认驱动 | SG2002 侧只需串口（已有） |
| 调试方式 | STM32 有 SWD，断点/单步/看变量；不用烧卡、不用复位整机 |
| 故障解耦 | SG2002 崩了，屏停在最后一帧仍在显示内容，属"显示降级不停车" |
| 风险前移 | 原来是"唯一无实测背书的环节"，现在变成最成熟的环节 |

**代价**：`Panel` 的渲染逻辑从 Rust 挪到 C，两套代码要在同一个文件里维护布局常量。可控。

### 2.2 硬件连接

屏接 STM32 的 SPI1（APB2 84 MHz，最高 42 MHz），DC/RST 用任意 GPIO。

| 信号 | STM32 引脚 | 说明 |
|---|---|---|
| SCK / MOSI | SPI1_SCK / SPI1_MOSI | 只写不读，MISO 不接 |
| CS | SPI1_NSS 或软件控制 | 单设备，软件控制更简单 |
| **DC** | 任意 GPIO（如 PB0） | 低=命令，高=数据 |
| **RESET** | 任意 GPIO（如 PB1） | 低有效，上电拉低 10 ms |
| BLK | 3.3 V 常亮 | 比赛不需要调光 |

初版按 **20 MHz** 跑通再上探 25–30 MHz。

### 2.3 初始化序列（最小必需集）

| 命令 | 参数 | 延时 | 作用 |
|---|---|---|---|
| `0x01` SWRESET | — | 120 ms | 软复位 |
| `0x11` SLPOUT | — | 120 ms | 退出睡眠 |
| `0x3A` COLMOD | `0x55` | — | **16 bit RGB565** |
| `0x36` MADCTL | `0x48` | — | MX\|BGR，按实际接线调 |
| `0x21` INVON | — | — | IPS 屏通常需要反显 |
| `0x29` DISPON | — | 20 ms | 开显示 |

`MADCTL` 的四个方向位（`MX=0x40 MY=0x80 MV=0x20`）按屏幕实际朝向试，**用一张方向已知的测试图确定**，别靠猜。上电花屏/偏色/边缘撕裂说明厂家还有 `0xB0`–`0xE8` 段的时序电源参数，对照该屏初始化表补齐，通常 2–3 轮。

### 2.4 分工与数据流

| 谁 | 做什么 |
|---|---|
| **SG2002** | 排版决策、选图、决定"该显示什么"；只发指令与位图 |
| **STM32** | 存静态模板与类名位图、逐行合成、SPI 写屏 |

**一次性下发（上电自检阶段）：**

| 内容 | 体积 | @921600 |
|---|---|---|
| 静态模板（标签、边框、分割线）1 bpp | ~4 KB | 0.05 s |
| 每类名称位图 144×28 1 bpp ×6 | 3 KB | 0.03 s |
| 数字字模（24 px / 56 px，0–9） | ~3 KB | 0.03 s |

**运行期（每件）：**

```
DISP <seq> <class> <done> <total>\n        // ≈ 25 字节 = 0.2 ms
```

**换类时**才追加下发该类缩略图：80×80 RGB565 = 12.8 KB = 0.11 s。

**这个划分是关键**：序号和总数是纯数字，STM32 用内置字模自己画；名称和缩略图只在换类时变。**每件的串口开销只有 25 字节**，对节拍的影响是 0.2 ms / 8700 ms。

### 2.5 刷新策略：逐行合成 + 局部窗口

**不能在 SRAM 里存整屏底图**：480×320×2 = 307 KB，而 F407 只有 192 KB SRAM。

改用**逐行缓冲**：STM32 维护一条 480 像素的行缓冲（RGB565 = 960 B），每行按"静态模板 + 动态内容"现场合成后经 SPI 送出。

| 项 | SRAM |
|---|---|
| 行缓冲 480×2 | 960 B |
| 静态模板（4 KB 位图，解压到片上） | ~8 KB |
| 类名位图 ×6 | 3 KB |
| 当前类缩略图 80×80×2 | 12.8 KB |
| 数字字模 | ~3 KB |
| **合计** | **≈ 28 KB / 192 KB** |

重绘用 `CASET`/`RASET`/`RAMWR` 开窗口，只送变化矩形：

| 区域 | 矩形 (x0,y0,w,h) | 像素 | 字节 | @25MHz |
|---|---|---|---|---|
| 序号区 | (192,40,272,80) | 21,760 | 43.5 KB | 14 ms |
| 名称区 | (192,128,272,48) | 13,056 | 26.1 KB | 8 ms |
| 总数区 | (192,188,272,56) | 15,232 | 30.5 KB | 10 ms |
| 缩略图 | (16,48,160,160) | 25,600 | 51.2 KB | 16 ms |
| 状态条 | (0,0,480,32) | 15,360 | 30.7 KB | 10 ms |
| **典型一件**（序号+名称+总数+状态条） | — | 65,408 | **130.8 KB** | **42 ms** |

42 ms 与运动并行，单件 8.7 s 里完全吃得下。**SPI 走 DMA**，合成和发送流水起来。

### 2.6 四字段布局（像素坐标，两端共用同一份常量表）

```
0                                                                479
┌────────────────────────────────────────────────────────────────┐ y=0
│ 运行中 · 第 3 件 / 共 12 件                          00:42      │ h=32
├──────────────┬─────────────────────────────────────────────────┤ y=32
│              │  名称                                            │
│   缩略图      │  红色圆柱                                        │
│   160×160    │                                                  │
│  (16,48)     │  总数   4 件                                     │
│              │  已分   2 件                                     │
│              │  ┌──────────────────────────────┐                │
│              │  │ 序号                    3    │  56px 大字     │
│              │  └──────────────────────────────┘                │
├──────────────┴─────────────────────────────────────────────────┤ y=280
│ ▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░  2/12                        │ h=40

```

| 字段 | 位置 | 字号 | 刷新时机 |
|---|---|---|---|
| 序号 | (192,180) | 56 px | 每件 |
| 名称 | (192,148) | 24 px | 换类时 |
| 图片 | (16,48) 160×160（80×80 源 2× 最近邻放大） | — | 换类时 |
| 总数（含已分） | (192,208) | 24 px | 每件 |
| 状态条 / 进度 | (0,0) / (0,280) | 16 px | 每件 |

**赛规硬性要求**：四字段任一错误，该件不得分；每件分拣后必须刷新。所以 `DISPLAY` 子状态里要**回读校验**：SG2002 发完 `DISP` 后由 STM32 回 `OK`，STM32 内部再校验一次"四个矩形都刷新过、字段非空"，不一致返回 `ERR`，SG2002 重发一次。

**名称的来源**：初赛物料自备，6 个类名在 `classes.json` 写死。抽签若换成未登记货物，走 §3.8 兜底分组，类名自动生成"形状·颜色"（如"圆形·红"），此时名称位图改为现场渲染后下发。

### 2.7 MCU 负载核算

| 任务 | 占用 |
|---|---|
| 3 轴步进脉冲 16 kHz | **TIM + DMA 硬件产生，CPU ≈ 0** |
| 真空泵 / 电磁阀 / 压力开关 | GPIO，微秒级 |
| SPI 刷屏 | DMA 搬运，CPU 只做合成 |
| 逐行合成（每件 65 K 像素 × ~10 指令） | ≈ 4 ms |
| 串口行解析 | UART IDLE 中断 + 环形缓冲 |
| 主状态机 + 看门狗 | 主循环 |

**脉冲由硬件定时器产生，CPU 中断抖动不影响脉冲精度** —— 这是把显示和运动放同一颗 MCU 上仍然安全的前提。

## 3　视觉：从像素到托盘坐标

### 3.1 取帧

这层必须重写：8 月版走 `/dev/video0` 的 V4L2，参考实现走自定义 ioctl，两套接口不通用。

```rust
trait Camera {
    fn open(&mut self) -> Result<Info, CamErr>;
    fn grab(&mut self) -> Result<Frame, CamErr>;   // Frame = 640×480 平面 YUV422 (I422)
    fn close(&mut self);
}
```

`I422`：`Y[W*H]` + `U[W*H/2]` + `V[W*H/2]`，共 614,400 字节。

YUV422 → RGB（BT.601，全范围）：

```
C = Y,  D = U - 128,  E = V - 128
R = clamp(C + 1.402·E,                 0, 255)
G = clamp(C - 0.344136·D - 0.714136·E, 0, 255)
B = clamp(C + 1.772·D,                 0, 255)
```

U/V 按 `x>>1` 取值（水平 2:1 子采样）。默认只用 Y 通道做分割，**只在判色时才转 RGB** —— 省掉 92% 的转换量。

### 3.2 标定：离线内参 + 在线仿射

**内参在 PC 上用 OpenCV 离线做，板上只查表。** 这是绕开"板上没有 OpenCV"的关键。

| 步 | 在哪 | 做什么 | 产物 |
|---|---|---|---|
| ① | PC（一次性） | 15 张棋盘图 → `cv2.calibrateCamera` → `K`、`dist` | 写进 `calib.json` |
| ② | PC（一次性） | 由 `K`、`dist` 反算 **81×61 控制网格**的去畸变映射 | `remap.bin`，**20 KB** |
| ③ | 板上启动 | 加载 `remap.bin`，双线性插值去畸变 | — |
| ④ | 板上标定阶段 | 托盘四角已知 mm 坐标 → DLT 求单应 `H`(3×3) | 写进 `calib.json` |

**为什么不存 640×480 逐像素映射表**：那是 1.2 MB（u16）到 2.4 MB（f32）。81×61 网格 + 双线性只有 20 KB，精度损失 <0.2 像素。

**单应求解**：4 点 → 8 个方程，高斯消元解 8 个未知量，约 60 行，**不需要线性代数库**。

**高度视差补偿**（货物有厚度，相机俯视）。点 P 在托盘面上，光心距托盘 `Hc`，焦距 `f`；物体顶部高 `h` 时成像位置比底部更远离画面中心：

```
X_true = X_meas · (1 - h/Hc)
Y_true = Y_meas · (1 - h/Hc)
```

即**按到画面中心的距离等比例收缩**，不是固定平移。`h` 用已知高度量块标一次；各类件高度差异大就按类存 `h`。

### 3.3 分割

**拍不到空盘**：货物开赛前已随机放好、不许触碰整理，所以不能用背景差分。只能靠"自备托盘深色哑光"这个前提做阈值分割。

```
mask = (V > τ_v) | (S > τ_s)
```

- `τ_v` 用 **Otsu** 在 V 通道直方图上自适应求（深底浅物的典型场景，Otsu 稳）
- `τ_s` 固定（约 0.35），兜住"深色但高饱和"的件（深红、深蓝）
- 形态学：**开运算 3×3** 去椒盐噪声 → **闭运算 5×5** 补反光造成的洞
- 只在托盘 ROI 内计算（由 `H` 反算到像素，约 500×420），省 30% 计算量

### 3.4 粘连处理

随机撒放必然出现两件贴在一起。**分不干净时宁可标记跳过，不要强行切。**

| 步 | 做法 |
|---|---|
| ① 距离变换 | 对掩膜做欧氏距离变换 `DT` |
| ② 寻种子 | `DT` 的局部极大值，且 `DT > 0.6 × r_single`（`r_single` = 单件内切圆半径中位数） |
| ③ 区域生长 | 从各种子在掩膜内多源 BFS，得到分割标签图 |
| ④ **面积校验** | 每块面积与单件面积中位数比，偏差 > 35% → 标记 `SPLIT_FAIL` |

`SPLIT_FAIL` 的件**不参与分类，直接进 SKIP**。硬切出来的坐标不准，吸不中就是放错。

### 3.5 形状特征

| 特征 | 符号 | 算法 | 用途 |
|---|---|---|---|
| 顶点数 | `N` | Douglas-Peucker，`ε = 0.02 × 周长` 后的顶点数 | 区分圆(8-12)/方(4)/三角(3)/六边(6) |
| 圆度 | `C` | `4πA / P²` | 圆≈1.0，方≈0.785，长条<0.4 |
| 填充率 | `F` | `A / (W·H)_bbox` | 区分凹形（星形、L 形） |
| 长宽比 | `R` | `max(W,H) / min(W,H)` | 区分长条与方块 |
| 面积 | `A` | 像素数 × `s²`（`s` = 每像素 mm） | 区分大小件 |
| 凸缺陷数 | `D` | 凸包减轮廓的连通区域个数 | 星形/L 形 |

`A`、`P` 用格林公式沿轮廓积分，不逐像素数。

### 3.6 颜色特征

```
① 白平衡归一：托盘上固定白色参考块，每轮开机算一次增益
   gain_ch = ref_target / ref_measured（RGB 三通道分别）
② 只统计前景像素且 S > S_min 的（排除高光与阴影）
③ H 直方图 36 bin（10° 一档）
④ H_med = 峰值 bin 及左右各 1 bin 的加权平均
⑤ 同时记录 S_med、V_med
```

`S_med < S_min` → 判为无彩色，走"白/灰/黑"三档（靠 `V_med` 分）。

### 3.7 六类匹配（主路径）

物料自备、类别闭集，主路径是**配置驱动的最近邻**，不是训练分类器 —— 抽签变了只改 `classes.json`。

```
d = Σ_k  w_k · |x_k - r_k| / σ_k

x  = (N, C, F, R, A, H_med)
r  = 该类标定得到的参考值
σ  = 该类标定阶段（每类采 10 件）的类内标准差
w  = {N:2.0, C:2.0, F:1.5, R:1.0, A:1.0, H_med:3.0}
```

| 条件 | 结果 |
|---|---|
| `d_min ≤ D_ACCEPT` 且 `d₂ - d₁ ≥ D_MARGIN` | 接受，`conf = 1 - d₁/D_ACCEPT` |
| `d_min ≤ D_ACCEPT` 但 `d₂ - d₁ < D_MARGIN` | **低置信 → SKIP**（两类太像，宁可不分） |
| `d_min > D_ACCEPT` | **低置信 → SKIP** |

`D_ACCEPT`、`D_MARGIN` 用测试集扫出来（正确率 ≥95% 且跳过率 ≤10% 的那组）。

### 3.8 兜底：无监督分组

若匹配接受率 < 60%（抽签换了不认识的货），自动切分组模式，类数不需要预先知道：

```
① 形状特征 Z-score 归一化
② DBSCAN(eps = 0.6, minPts = 2) → 形状簇
③ 每个形状簇内按 H_med 排序，相邻差 > 25° 处切开 → (形状 × 颜色) 簇
④ 簇大小 ≥ 2 才成立；单件簇标"待定"，走 SKIP
⑤ 生成类名 "{形状词}·{颜色词}"，按 (簇中心 H, 平均面积) 排序编号 1..K
```

赛规判据本来就是"形状相同且颜色相同"，自动生成的名字照样成立。

### 3.9 输出

```rust
struct Detection {
    id:      u8,
    class:   Option<u8>,   // None = 跳过
    cx_mm:   f32,          // 托盘坐标，原点左下角
    cy_mm:   f32,

```

**上层永远只见 mm，不见像素。**

## 4　控制：协议、状态机、任务队列

### 4.1 串口协议

921600 8N1（F407 支持到 10 Mbps+），ASCII 文本行，`\n` 结尾。**走 USB-TTL**，即用已验证的 DWC2 主机栈，不碰板载 UART pinmux。

| 方向 | 报文 | 应答 | 说明 |
|---|---|---|---|
| PC→MCU | `PING` | `PONG` | 2 s 一次，无运动也发 |
| PC→MCU | `GOTO <x> <y>` | `OK` … `DONE` | 单位 0.1 mm 整数，避免浮点解析 |
| PC→MCU | `Z <v>` | `OK` … `DONE` | 同上 |
| PC→MCU | `VAC <0\|1>` | `OK` | **幂等** |
| PC→MCU | `HOME` | `OK` … `DONE` | 回零 + 限位确认 |
| PC→MCU | `STOP` | `OK` | 立即停脉冲 |
| PC→MCU | `CFG <k> <v>` | `OK` | 速度/加速度/软限位 |
| PC→MCU | `DISP <seq> <cls> <done> <total>` | `OK` | 显示刷新 |
| PC→MCU | `THUMB <cls> <12800 bytes>` | `OK` | 换类时下发缩略图 |
| MCU→PC | `PSW <0\|1>` | — | 压力开关**变化时主动上报** |
| MCU→PC | `ERR <c> <msg>` | — | `E01` 超行程 `E02` 限位未找到 `E03` 未知指令 `E04` 显示失败 |

规则：
- 每条必有 `OK`；**有运动的必须有 `DONE`**
- PC 侧等待上限 500 ms，超时重发一次，3 次失败走降级
- MCU 侧 UART IDLE 中断 + 环形缓冲，**解析在中断里，执行不在中断里**

### 4.2 主状态机

```
BOOT → SELF_TEST → STANDBY ──一键启动──▶ ARMED → RUNNING → FINISH
            │                                        │
            └──自检不过──▶ FAULT                     └──异常──▶ ABORT
```

| 状态 | 做什么 | 退出条件 |
|---|---|---|
| `SELF_TEST` | 标定单点校验、串口握手、**屏模板下发与自检**、真空自检 | 全绿 |
| **`STANDBY`** | 取图 → 分割 → 分类 → 生成任务队列 → **下发 6 类名称位图** → **关相机** | 队列非空且屏资源就绪 |
| `ARMED` | 只等触发，心跳持续 | 一键启动 |
| `RUNNING` | 逐件出队执行 | 队列空 / 异常 |
| `FINISH` | 停泵、停轴、显示汇总 | — |

**`STANDBY` 是重心**：所有慢操作压在这里，`RUNNING` 里不允许出现任何"算一下"的动作。**相机在这里关掉**，开赛后不再打开 —— 这就是规避 UVC 挂死的办法。

### 4.3 单件子状态机

```
NAV_PICK → Z_DOWN → VAC_CHK → Z_UP → NAV_BIN → Z_DOWN → VAC_OFF → Z_UP → DISPLAY → NEXT
                        │
                        └ 压力不达标 → 原地重吸(≤2) → 仍失败 → SKIP
```

| 子状态 | 关键点 | 超时 |
|---|---|---|
| `NAV_PICK` | 走到抓取点上方 | 3.0 s |
| `Z_DOWN` | 下降 | 2.0 s |
| `VAC_CHK` | **停稳 ≥100 ms 再读压力**；不达标绝不进 `Z_UP` | 1.5 s |
| `Z_UP` | 抬起 | 2.0 s |
| `NAV_BIN` | 走到盒位（换类时先发 `THUMB`） | 4.0 s |
| `Z_DOWN` / `VAC_OFF` | 到盒内才破真空，破完读压力确认 | 2.0 s / 0.5 s |
| `DISPLAY` | **必须先于下一件的第一个动作**，等 `OK` 后自检四字段 | 0.3 s |
| `SKIP` | **跳过 ≠ 停住**，转向下一件也走运动指令 | — |

超时不是"再等等"，是**立即进 SKIP 或 ABORT**。`DISPLAY` 失败不停车：显示坏了最多丢分，停下来就是整轮归零。

### 4.4 任务队列

```
① 每个类 → 一个固定盒位
② 类内抓取顺序：贪心最近邻（单类 ≤4 件）
③ 类间顺序：盒位固定，穷举 6! = 720 个排列，取总路程最短
④ 输出 Vec<Job>，开赛前一次算完
```

720 次浮点累加在 C906 上 <1 ms，**不需要 TSP 启发式**。

### 4.5 心跳与降级

```
PC → MCU：每 2 s 一次 PING（即使没运动）
MCU → PC：每条指令回 OK/DONE；5 s 内没收到任何指令 → 自主微动作
```

**MCU 自主微动作是最后一道保险**：PC 崩了、串口断了，装置仍在动，裁判看到的是"还在工作"，而不是"15 秒静止判死"。约束：只在 MCU 空闲时执行，幅度 2 mm，不越限位。

| 现象 | 判据 | 动作 | 继续? |
|---|---|---|---|
| 置信度不足 | `conf < CONF_MIN` | SKIP 该件 | ✅ |
| 压力不达标 | 重吸 2 次仍失败 | SKIP | ✅ |
| 串口单次超时 | 500 ms 无应答 | 重发 ≤3 次 | ✅ |
| 串口连续失败 | 3 次都失败 | `HOME` + 重建连接 | ⚠️ |
| 显示失败 `E04` | — | 重发一次，仍失败则继续但告警 | ✅ |
| MCU `E01` 超行程 | — | ABORT 本轮 | ❌ |
| 主线程心跳停 >3 s | watchdog 发现 | 开赛前重启进程；开赛后交给 MCU | ❌ |

**容错优先级：不停住 > 不放错 > 多完成。**

## 5　系统实现

### 5.1 进程与线程

**单进程 + 三线程。** 不拆多进程：共享只读任务队列的收益远大于隔离收益。

| 线程 | 职责 | 绝对不做 |
|---|---|---|
| `main` | 唯一状态机；**唯一写串口的人** | 不做耗时图像处理 |
| `display` | 取快照 → 算脏矩形 → 发 `DISP` 行（**不碰屏**） | 不阻塞主线程（持锁 <1 ms） |
| `watchdog` | 监控主线程心跳、串口心跳、队列进度 | 不直接操作硬件 |

**串口只给主线程**：两个线程同时写串口是这类系统最常见的偶发故障源。所有发指令路径收敛到 `Link::send()`。

### 5.2 关键接口

```rust
trait Camera { fn grab(&mut self) -> Result<Frame, CamErr>; fn close(&mut self); }

trait Panel {
    fn push_static(&mut self) -> Result<(), LinkErr>;                        // 上电一次性
    fn push_names(&mut self, names: &[Bitmap1bpp; 6]) -> Result<(), LinkErr>; // STANDBY
    fn push_thumb(&mut self, class: u8, rgb565_80x80: &[u16]) -> Result<(), LinkErr>;
    fn show(&mut self, seq: u8, class: u8, done: u8, total: u8) -> Result<(), LinkErr>;
}

trait Link {
    fn goto(&mut self, x_mm: f32, y_mm: f32, timeout: Duration) -> Result<(), LinkErr>;
    fn z(&mut self, mm: f32, timeout: Duration) -> Result<(), LinkErr>;
    fn vac(&mut self, on: bool) -> Result<(), LinkErr>;
    fn wait_done(&mut self, timeout: Duration) -> Result<(), LinkErr>;
    fn ping(&mut self) -> Result<(), LinkErr>;
}
```

模块间只通过这些接口通信，换实现不改调用方。

### 5.3 内存预算

| 项 | 字节 |
|---|---|
| YUV 帧 640×480 I422 | 614 KB |
| RGB 工作帧 640×480×3 | 921 KB |
| 掩膜 + 标签图（2 张 u8） | 614 KB |

### 5.5 无板开发（最重要的工程约束）

**每个模块必须能在 PC 上离线跑**，否则调试会被硬件占满。

| 模式 | 作用 | 验证什么 |
|---|---|---|
| `--replay <dir>` | 读磁盘上已存的 640×480 帧 | 分割、特征、匹配的全部回归 |
| `--fake-panel` | 把 `DISP` 序列渲染成 PNG | 排版、四字段（与 STM32 侧共用常量表） |
| `--dry-run` | 串口打桩，只打印指令与轨迹 | 状态机、任务队列、节拍 |
| `--sim-fault` | 注入串口超时 / 低置信 / 吸空 | 降级矩阵每一行 |

**固定测试集**：6 类 × 姿态 + 粘连 + 遮挡 + 边缘，约 60 张，回归基线。改任何参数先跑一遍。
